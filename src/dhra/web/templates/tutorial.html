Getting started

DHRA keeps every claim traceable to a source, and shows you when it can't. Everything below works the same whether you click through this page or type dhra commands in a terminal — use whichever fits the moment.

1. Add something to the corpus

Add item → — paste text, or upload a .pdf/.png/.jpg/.tif/.xml file. PDFs are read with pdftotext, images with real Tesseract OCR — not simulated. You'll land on the new item's page once it's in.

Terminal equivalent:

dhra ingest --source-id "my_archive" --text "paste your text here"
dhra ingest --source-id "my_archive" --file path/to/scan.pdf

2. Search it

Search → is literal, case-insensitive full-text search. A hit shows you exactly where it came from (a locator you can click to see the full source and its provenance) and why it matched. A miss tells you how much of the corpus was actually searched and how legible it was — never just "not found".

dhra search "your query"

3. Assess a claim

Found evidence for something? Click use as evidence for a claim next to any search result, or go to Claims → directly. You write the claim in your own words and list the locators that support (or contradict, or negate) it — DHRA's own code decides the status from that list, never a model, never a number:

E1attested
E5single witness
E4contested
E6unsupported

Hover any status code anywhere in the app to see what it means — that tooltip is the only place a status's meaning lives.

dhra claims assess my-claim-id --text "the claim, in your words" \
  --supporting item_id,rep_id,start,end

4. Check the corpus for bias

Aggregate → always shows a bias report first — source concentration, uneven date coverage, languages you expected but never see, failed acquisitions — before any breakdown of the corpus itself. It's not something you have to remember to check.

dhra aggregate

5. Exclude, don't delete

Bad OCR, wrong date range, off-topic — excluding an item takes it out of search and aggregates, but the item itself is never deleted. Exclusions → lists every one, grouped by reason, restorable in one click.

dhra exclusions list
dhra exclusions restore <item_id>

6. Track new publications

Save a keyword query and Updates → checks it against OpenAlex's open works index whenever you ask — no background process, so nothing is watching between checks. New matches show title, authors, date and a link; dismiss the ones you don't need, restore them if you change your mind.

dhra watch add "Ottoman manuscripts"
dhra watch check
dhra watch candidates

7. See exactly what happened

Trace → is the audit trail: every search, every exclusion, every claim assessment, as an event with a timestamp. Nothing in this app changes corpus state outside that log.

Working from a terminal or a script

Every command above is real, scriptable, and talks to the same store directory as this page — point --store (or the DHRA_STORE_DIR environment variable) at it:

export DHRA_STORE_DIR=/path/to/your/store
dhra search "some query"
dhra web --port 8420   # launch this UI against the same store

An MCP-connected agent (e.g. Claude Code/Desktop) can also drive DHRA directly — see dhra.mcp_server in the repo.
